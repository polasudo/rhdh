
Need to do some automation?

Steps to follow:

1. Request a CMDB ID if you don't have one already for your product/service:

* link:https://redhat.service-now.com/help?id=kb_article_view&sysparm_article=KB0011576[Instructions]
* link:https://redhat.service-now.com/help?id=sc_cat_item&sys_id=88c9c7bb137f1340196f7e276144b020[SNOW form]
* link:https://redhat.service-now.com/help?id=rh_ticket&table=sc_req_item&sys_id=fe45a23ddb14b994bd297e83e29619c9[Example request]
* link:https://redhat.service-now.com/nav_to.do?uri=%2Fcmdb_ci_business_app.do%3Fsys_id%3D4745e23ddb14b994bd297e83e296190c%26sysparm_record_target%3Dcmdb_ci_business_app%26sysparm_record_row%3D1%26sysparm_record_rows%3D1%26sysparm_record_list%3D123TEXTQUERY321%253Drhdh%255EORDERBYzztextsearchyy[CMDB listing]

2. Request an email address (as a google group):

* link:https://redhat.service-now.com/help?id=sc_cat_item&sys_id=15e540dc2bb3b0004c71dc0e59da15b8[SNOW form]
* link:https://redhat.service-now.com/help?id=rh_ticket&table=sc_req_item&sys_id=69a73fa1dbac7510bd297e83e29619db[Example request]
* link:https://groups.google.com/u/1/a/redhat.com/g/rhdh-bot[google group]

3. For GitLab

a. Request a service account for GitLab:
 
* link:https://redhat.service-now.com/help?id=sc_cat_item&sys_id=ec649e491bc74d587f9bfc8f034bcbe3[SNOW form]
* link:https://redhat.service-now.com/help?id=rh_ticket&is_new_order=true&table=sc_request&sys_id=4afb6e51db6c3110bd297e83e29619cb[Example request]

b. Grant access for a Service Account in GitLab:

* link:https://redhat.service-now.com/help?id=kb_article_view&sysparm_article=KB0012059[KB article / instructions for requester]  - send email to  it-alm-tickets@redhat.com
* link:https://redhat.service-now.com/help?id=kb_article_view&sysparm_article=KB0020877[KB article / instructions for IT admin]
+
NOTE: email will generate a SNOW ticket, eg., link:https://redhat.service-now.com/help?id=rh_ticket&table=incident&sys_id=6f0125131ba439544cec766dcc4bcba7[Example request]

c. Configure the GitLab repo to use your service account's keytab
+
* open an incognito mode browser
* log in using bot's email address and password; if this is the first time logging in, set a new password. *Write it down!*
* generate an SSH key (if one does not already exist). *Write it down!*
* generate a Personal Access Token. *Write it down!*
* upload PAT in a Secure File - see https://gitlab.cee.redhat.com/rhidp/rhdh/-/settings/ci_cd then expand section "Secure Files"
* update the ci script to use the new file - https://gitlab.cee.redhat.com/rhidp/rhdh/-/commit/e8e28a209099aba27db9210edc4a258572817a97

d. Verify pipeline works with bot's PAT:
+
* push a link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/commit/bd3c65c94b5b322a018c0287fc864508e9497aae[no-op change] to the repo which the `sync.sh` will override
* link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/pipeline_schedules[trigger the pipeline] to verify the bot can push using its PAT, link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/jobs/14751080[reverting the no-op commit]

e. Additional secure file storage can be seen in link:secrets/README.adoc[secrets/README], using git-crypt.

4. For GitHub

a. Using the above email address, sign up for a new GitHub account
+
* log in using bot's email address and password; if this is the first time logging in, set a new password. *Write it down!*
* check the Google group for the authorization code
* decline the message posted to the group

b. Store the password
+ 
* Commit the password to a secure location (eg., a gitlab project's secrets file, encrypted with git-crypt or similar)

c. Add the new bot user to the various projects for which it needs to be able to commit changes, trigger workflows, etc.
