## Building locally

Upstream, you can build the Containerfile in https://github.com/redhat-developer/rhdh/tree/main/build/containerfiles a number of ways. See link:https://github.com/redhat-developer/rhdh/tree/main/build/containerfiles/README.adoc[README] for details.

In this repo, you can create a merge request against link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/distgit/containers/rhdh-hub/Containerfile[distgit/containers/rhdh-hub/Containerfile] and watch as Konflux attempts to build your changes.

If you need access to the internal RH Konflux instance at https://konflux-ui.apps.stone-prod-p02.hjvn.p1.openshiftapps.com/ns/rhdh-tenant/applications/rhdh-1/activity/pipelineruns see link:PERMISSIONS.adoc[PERMISSIONS.adoc].

Note that changes done directly to the Containerfile may be undone when link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/ci/sync-midstream.sh[sync-midstream.sh] runs to fetch the latest content from https://github.com/redhat-developer/rhdh/, so it's important to remember to:

* apply your changes upstream too
* run the sync script locally (with `--nocommit` or `--nopush`) to validate your desired changes downstream have not been overwritten by upstream changes.
* adjust the sync script regularly to adapt to changes upstream


## Triggering builds

### Triggering hub and operator builds

. Use the link:../build/scripts/triggerRespin.sh[triggerRespin.sh] script to pull the latest from upstream into the GL midstream repo.

. If all goes well, you should also get a new bundle build that includes the latest hub and operator. 

### Triggering operator-bundle builds

. To check that the CSV is up to date with the latest hub and operator images, run the link:../build/scripts/checkImagesInCSV.sh[checkImagesInCSV] script:
+
```
./build/scripts/checkImagesInCSV.sh quay.io/rhdh/rhdh-operator-bundle:1.4-83 -qq -y
```

. Use the link:../build/scripts/triggerRespin.sh[triggerRespin.sh] script to pull the latest from upstream into the GL midstream repo.
+
```
./build/scripts/triggerRespin.sh -v 1 bun
./build/scripts/triggerRespin.sh -v 1.6 bun
```

### Triggering FBC builds

* Run link:../build/scripts/renderCatalogs.sh[build/scripts/renderCatalogs.sh] to create new File Base Catalog (FBC) fragments, then commit the changes.

* Or, push a change to the files in .tekton/fbc-* to trigger new FBC builds. 

* New FBCs will be published to link:https://quay.io/rhdh/iib[quay.io/rhdh/iib] and can be link:https://github.com/redhat-developer/rhdh-operator/blob/main/.rhdh/docs/installing-ci-builds.adoc[installed] using the following script:

* link:https://github.com/redhat-developer/rhdh-operator/blob/main/.rhdh/scripts/install-rhdh-catalog-source.sh[install-rhdh-catalog-source.sh]

### Triggering helm chart updates

Starting with 1.4, helm charts are automatically published for every new rhdh-hub-rhel9 container build.

For 1.4, CI charts are published to https://github.com/rhdh-bot/openshift-helm-charts/tree/rhdh-1.4-rhel-9. To install, see https://github.com/rhdh-bot/openshift-helm-charts/tree/rhdh-1.4-rhel-9/installation

As of 1.5, CI charts are published as OCI artifacts to https://quay.io/rhdh/chart. To install, see https://github.com/rhdh-bot/openshift-helm-charts/tree/rhdh-1-rhel-9/installation

## Triggering Konflux builds for Pull Requests

Currently, changes in the upstream GH repos are not buildable immediately in Konflux, but must be transformed for use there.

So, if you want to test an upstream change in Konflux, here are the steps:

1. Draft your upstream PR, and push it to a fork or topic branch at Github
2. Edit the link:../upstream_repos.yml[upstream_repos.yml] file to point to your topic branch or fork
3. Locally, run:
+
```
./build/ci/sync-midstream.sh --nopush --nocommit --force --next -b rhdh-1-rhel-9
```

4. Commit your changes to a topic branch, and create a gitlab Merge Request
5. Watch it building in Konflux at https://konflux.apps.stone-prod-p02.hjvn.p1.openshiftapps.com/application-pipeline/workspaces/rhdh/applications/rhdh-1/activity/pipelineruns?name=pull

## Collecting build logs offline

Konflux will trash your build and release pipeline logs after only a few days. However, you can collect them offline WHILE they're running.

. First, install opc from https://docs.openshift.com/pipelines/latest/tkn_cli/installing-tkn.html

. Then once a pipeline is running, collect the log:

* pipeline run log (pull request)
+
```
pr=abcde # hash code for the specific pipeline
opc pr logs -n rhdh-tenant rhdh-hub-1-on-pull-request-${pr} -f | tee ~/tmp/rhdh-hub-1-on-pull-request-${pr}.log.txt &
```

* pipeline run log (push)
+
```
pr=abcde # hash code for the specific pipeline
opc pr logs -n rhdh-tenant rhdh-hub-1-on-push-${pr} -f | tee /tmp/rhdh-hub-1-on-push-${pr}.log.txt &
```

* managed pipeline (pushing containers or FBCs, to stage or prod)
+
```
pr=9k68t # hash code for the specific managed pipeline
opc pr logs -n rhtap-releng-tenant managed-${pr} -f | tee ~/tmp/release-pipeline-managed-${pr}.log.txt
```

## Searching for old build logs in Splunk

If you don't have an offline cache of the build log you need, you can search for it in Splunk.

. First, get access to Splunk. See link:PERMISSIONS.adoc[Permissions guide].

. Then, search Splunk for a recent managed pipeline push (for a Konflux Release). For example, to find the 1.5.z release pushes:
+
```
index=rh_rhtap_production_app kubernetes.namespace_name=rhtap-releng-tenant kubernetes.labels.tekton_dev_taskRun="managed-*" message="*quay.io/redhat-pending/rhdh----rhdh-hub-rhel9:1.5.*-source*" | table _time kubernetes.labels.tekton_dev_pipeline kubernetes.labels.tekton_dev_taskRun message
```

. Results for the above sample query: 

* For the 1.5.0 release: `managed-n7v8z`
* For the 1.5.1 release: `managed-cc58n`

. You can then search the full managed pipeline's logs. For example:

```
index=rh_rhtap_production_app kubernetes.namespace_name=rhtap-releng-tenant kubernetes.labels.tekton_dev_taskRun="managed-n7v8z*" message="*" | table _time kubernetes.labels.tekton_dev_pipeline kubernetes.labels.tekton_dev_taskRun message
```
