### Jenkins orchestraton for PRs and pushes

Jenkins is used to coordinate all the builds, including triggering PNC builds of yarn artifacts for PIB and OSBS builds for RHDH containers. 

Some tasks are manual as the configuration changes infrequently; other tasks are automatic in response to upstream events. 

. link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/pipeline-seed/[Pipeline seed] job - run every time a merge request is pushed to `cpaas-products`, or run *manually* for direct commits 

. link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/honeyBadger-pipeline/[Honey Bager pipeline] - run *manually* for any changes to HB config in link:https://gitlab.cee.redhat.com/cpaas-products/rhdh/-/blob/main/versions/rhdh-1.0.0/product.yml[product.yml] or link:https://gitlab.cee.redhat.com/cpaas-products/rhdh/-/blob/main/versions/rhdh-1.0.0/release.yml[release.yml]

. link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/[Build and release pipeline] jobs - run automatically for merges to upstream repos; may need to be run *manually* for some commits (eg., midstream?)

### Downstream CI builds based on upstream changes

. Check for recent changes in https://github.com/janus-idp/backstage-showcase/commits/1.0.x (or main branch) since the last build have been synced to midstream as a new MR, eg., link:https://github.com/janus-idp/backstage-showcase/pull/305[PR 305] -> link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/merge_requests/33[MR 33]:
.. link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/poll-all-upstream-sources/[poll-all-upstream-sources] -> link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/rhdh/job/poll-upstream-sources/[poll-upstream-sources]
. Verify that this MR has been checked...
.. link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/gitlab-event-dispatcher/30/[gitlab-event-dispatcher] -> link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/rhdh/job/check-patch/27/[check-patch] -> link:http://brewweb.engineering.redhat.com/brew/taskinfo?taskID=53169867[brew container build] (scratch from cpaas junkyard)
. ... then merged...
.. link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/gitlab-event-dispatcher/31/[gitlab-event-dispatcher] -> link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/rhdh/job/check-merged/3/[check-merged] 
. ... then built.
... link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/build-pipeline/11/[build-pipeline] -> link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/rhdh/job/rhdh-hub-rhel9-container/job/rhdh-hub-rhel9-container/8/[rhdh-hub-rhel9-container] -> link:http://brewweb.engineering.redhat.com/brew/taskinfo?taskID=53170593[brew container build] -> `registry-proxy.engineering.redhat.com/rh-osbs/rhdh-hub-rhel9:1.0-3`

. Once the above brew build is done, the link:https://jenkins-cpaas-rhdh.apps.cpaas-poc.r6c9.p1.openshiftapps.com/job/rhdh-1.0.0/job/release-pipeline/[release-pipeline] should add the container build(s) to the link:https://errata.devel.redhat.com/advisory/114828[errata] and set the correct CDN metadata. These steps are controlled by the following files:
* link:https://gitlab.cee.redhat.com/cpaas-products/rhdh/-/blob/main/versions/rhdh-1.0.0/product.yml[product.yml] (see `product.honeybadger` and `product.components.builds`)
* link:https://gitlab.cee.redhat.com/cpaas-products/rhdh/-/blob/main/versions/rhdh-1.0.0/release.yml[release.yml] (see `release.pipelines["release"].stages`)

Repeat the above steps for subsequent RC builds.
