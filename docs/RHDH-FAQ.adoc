# Red Hat Developer Hub (RHDH) - FAQ

Some quickstart tips for building RHDH 1.y wih Gitlab and Konflux pipelines:

## How to respin

### How to respin for upstream or midstream changes

You can force a respin using this script: https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/scripts/triggerRespin.sh[build/scripts/triggerRespin.sh]

See link:RHDH-gitlab.adoc[RHDH-gitlab.adoc]

### How to force a respin without an upstream change

You can force a respin using this script: https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/scripts/triggerRespin.sh[build/scripts/triggerRespin.sh]

See link:RHDH-gitlab.adoc[RHDH-gitlab.adoc]

### How to force a build in Konflux only without any upstream or midstream changes

You can force a Konflux build respin by editing one of the .tekton/ pipeline files. For example, change the `max-keep-runs` value from 6 to 7 or 7 to 6:

```
$➔ git diff HEAD~1
diff --git a/.tekton/rhdh-operator-1-5-push.yaml b/.tekton/rhdh-operator-1-5-push.yaml
index 3faad8a25..b4cdf2f40 100644
--- a/.tekton/rhdh-operator-1-5-push.yaml
+++ b/.tekton/rhdh-operator-1-5-push.yaml
@@ -5,7 +5,7 @@ metadata:
     build.appstudio.openshift.io/repo: https://gitlab.cee.redhat.com/rhidp/rhdh/-/tree/{{revision}}
     build.appstudio.redhat.com/commit_sha: '{{revision}}'
     build.appstudio.redhat.com/target_branch: '{{target_branch}}'
-    pipelinesascode.tekton.dev/max-keep-runs: "7"
+    pipelinesascode.tekton.dev/max-keep-runs: "6"
```

This can also be done with link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/scripts/triggerRespin.sh#L38[triggerRespin.sh -k].

Commit your change to the midstream gitlab repo, using the keyword `[ci skip]` at the END of the commit message.

This will skip gitlab pipeline processing and only trigger a Konflux pipeline against the midstream.

### How to disable/skip pipelines

To skip the Gitlab pipeline:

Commit your change to the midstream gitlab repo, using the keyword `[ci skip]` at the END of the commit message.

To skip BOTH the Gitlab and Konflux pipelines:

Commit your change to the midstream gitlab repo, using the keyword `[ci skip]` at the START of the commit message.

## How can I see build or pull request logs after they're garbage collected?

Best answer is to collect them WHILE they're running and store them offline, since they'll be garabage collected. Known issue: https://issues.redhat.com/browse/KONFLUX-6454

First, install opc from https://docs.openshift.com/pipelines/latest/tkn_cli/installing-tkn.html

```
pr=abcde # some hash code for the specific pull request PipelineRun (pr)

# for a build pipeline
opc pr logs -n rhdh-tenant rhdh-hub-1-on-push-${pr} -f | tee /tmp/rhdh-hub-1-on-push-${pr}.log.txt &

# for a pull request
opc pr logs -n rhdh-tenant rhdh-hub-1-on-pull-request-${pr} -f | tee ~/tmp/rhdh-hub-1-on-pull-request-${pr}.log.txt &
```

## How can I see managed pipeline logs (for releases)?

Best answer is to collect them WHILE they're running and store them offline, since they'll be garabage collected. Known issue: https://issues.redhat.com/browse/KONFLUX-6454

To store a log offline, first install opc from https://docs.openshift.com/pipelines/latest/tkn_cli/installing-tkn.html


Then:
```
opc pr logs -n rhtap-releng-tenant managed-9k68t -f | tee /tmp/rhtap-releng-tenant managed-9k68t.log.txt
```
