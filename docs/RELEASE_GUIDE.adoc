 # Release Guide for RHDH 1.4+

This document seeks to explain the whole end-to-end process for releasing RHDH, from branch creation to GA push.

## Code Freeze / Blockers Only / New Stream Day

Run the branch creation script whenever dev is done (or nearly done) and it's time for feature (or code) freeze.

Once the branches are created, expect a flurry of last minute cherrypicks and requests for "can I include this non-blocker item too?" :this-is-fine: :this-is-the-way:

**Reject those requests** and send them to PM/QE/Doc for approval as these should have already landed in the LOCKED test/doc plan weeks ago.

### Onboard new application & components

New application, component, test, RP, and RPA configuration is required to create a new 1.5 stable branch.

See link:https://gitlab.cee.redhat.com/releng/konflux-release-data/-/merge_requests/?scope=all&state=merged&author_username=nboldt[konflux-release-data] for details.

### For a z-stream update, first do this

- collect the fixes in janus plugins + community plugins, and verify that they've been released to npmjs.com
- collect the updated plugin versions into showcase, and verify a downstream build has succeeded

### For all builds (y and z-stream)

- Use link:../build/scripts/kfuxRelease.sh[kfuxRelease.sh] to push the latest snapshot to stage 
- coordinate with QE and Doc via slack and email notifications of RC builds and progress of testing, doc readiness, etc.
- remind QE to announce test completion; watch while the builds are pushed (1-2 hrs?); complain on slack in various rel-eng channels if things break while pushing

### Once the containers have shipped 

- re-render FBCs to refer to registry.redhat.io instead of quay.io
- generate the helm chart PR for the openshift helm charts repo; monitor until it's merged
- release the FBCs to production
- smoke test the operator and helm installs
- notify Docs that they can release the latest RN updates
- tag the repos w/ new 1.y.z tag; bump the repos 1.y.(z+1) to prepare for subsequent releases
- for a .0 release, remove EOL versions of RHD from Comet

### Extended Summary
|===
| **Step** | **Key Actions & Required Scripts** | **Responsible Team**

| **1. Code Freeze** | Ensure all changes are merged before freeze. Reject non-blocker requests and route them to PM/QE/Docs. Test/documentation plans must be locked. | Release Engineering

| **2. Branch Creation** | Run the branch creation https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/scripts/tagRelease.sh?ref_type=heads[tagRelease] script:
```export GITHUB_TOKEN=<your_GH_token>
./build/scripts/tagRelease.sh -t 1.4 --branchfrom main -gh release-1.4
```
This script creates link:https://github.com/redhat-developer/rhdh/branches/all?query=release-1.4[release-1.4] and link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/tree/rhdh-1.4-rhel-9[rhdh-1.4-rhel-9] branches and updates `main`. | Release Engineering

| **3. Build & Test** | Tekton Pipelines for builds are triggered automatically when commits happen in the upstream GH repos. File Based Catalog fragments (FBCs) must be built by hand at intervals until link:https://issues.redhat.com/browse/RHIDP-5888[RHIDP-5888] is resolved . Run automated tests to ensure stability. Review Tekton pipeline status: link:../.tekton/README.adoc[Tekton Pipelines]. | QE, Engineering

| **4. Release Candidate (RC)** | **Disable scheduled pipelines** to prevent unapproved changes:  
Go to link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/pipeline_schedules[pipeline schedules], uncheck *Activated*, and save changes.

**Update the FBCs using the https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/scripts/renderCatalogs.sh?ref_type=heads[renderCatalogs.sh] script:**
```./build/scripts/renderCatalogs.sh
```
If replacements are incorrect, modify `catalog-template.json` and rerun the script. 

**NOTE**: if multiple releases are in flight, remember to re-render FBCs after each GA push in order to not accidentally delete freshly released operators. | Release Engineering, PM, QE

| **5. GA Preparation** | Update documentation and release notes.

Check PRs for Release Notes: link:https://github.com/redhat-developer/red-hat-developers-documentation-rhdh/[RHDH Docs Repo].
Run update scripts:
```./modules/dynamic-plugins/rhdh-supported-plugins.sh
./modules/release-notes/single-source-release-notes.py
```
Notify QE and Security for final validation. | Security, Docs, QE

| **6. GA Release** | **Trigger container release:**
```./build/scripts/kfuxRelease.sh --prod -c rhdh-operator-bundle -v 1.4.2 --cve /tmp/RHDH\ CVE\ Management\ -\ 1.4.2.csv
```

**Trigger the Helm Chart release:**
```./build/helm/prepare.sh --chart-version 1.4.2 --rhdh-version 1.4-132 --chart-branch release-1.4 --catalog git@github.com:rhdh-bot/openshift-helm-charts.git --publish
```
See PR: link:https://github.com/openshift-helm-charts/charts/pull/1556[Helm Chart PR].

**Trigger FBC release:**
```./build/scripts/kfuxRelease.sh --prod --fbc :1.4.2 -v 1.4.2 --debug
```

**Tag repositories:**
```./build/scripts/tagRelease.sh -v 1.4.2 -t 1.4 -gh release-1.4 -pd rhdh-1.4-rhel-9 -ghtoken $GITHUB_TOKEN
``` | Release Engineering

| **7. Post-Release** | For a .0 releaase, **Delete EOL versions** from Comet: link:https://comet.engineering.redhat.com/containers/repositories?view=myRepos&filter=repoPath:rhdh[Comet].

Monitor Quay image updates.

Update pipeline runner images **at least once per quarter**. | Release Engineering
