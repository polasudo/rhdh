## Onboarding a new person

1. Ask that person to go to https://konflux.apps.stone-prod-p02.hjvn.p1.openshiftapps.com/application-pipeline/workspaces/rhdh/applications
2. Ask that person to log in, register, click "join the waitlist", refresh their browser
3. Ask that person for their username / default workspace. This is likely their kerberos username, but might differ.
4. Add that person here: https://konflux.apps.stone-prod-p02.hjvn.p1.openshiftapps.com/application-pipeline/access
5. Once added, you can change their access level to contributor, maintainer, or admin. 

## Onboarding a new y-stream release

Once a quarter, new branch are created in GitHub called `release-1.y` for the new release. 
In the link:https://gitlab.cee.redhat.com/rhidp/rhdh[rhidp/rhdh Gitlab repo], an equivalent branch called `rhdh-1.y-rhel-9` is created.
Once these exist, a new Application, with 3 (or more) components can then be added. 

### Component Nudging

To trigger a build of the FBCs when a new operator-bundle image has been published, link:https://konflux-ci.dev/docs/how-tos/configuring/component-nudges/#in-the-ui[component nudging] is required. This should be configured so that for any new build of the rhdh-hub or rhdh-operator containers, a new rhdh-operator-bundle is theen built; once that is built, the bundle should nudge the FBC applications to update those with fresher digests.

## File Based Catalogs (FBCs)

FBCs replace IIBs (index bundles) in RHDH 1.4+.

### Building a new FBC or set of FBCs

See link:../build/scripts/renderCatalogs.sh[renderCatalogs.sh].

### Adding a new Application and Component to build FBCs for a new OCP version

This should only be done once every 6mo or so, when a new OCP version is released and a new version of registry.redhat.io/openshift4/ose-operator-registry-rhel9 becomes available.

1. Go to https://konflux.apps.stone-prod-p02.hjvn.p1.openshiftapps.com/application-pipeline/workspaces/rhdh/applications

2. Update defaults in link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/scripts/renderCatalogs.sh[build/scripts/renderCatalogs.sh]

3. Create a new Application and Component. Note that an MR will be generated to add new pipelines to https://gitlab.cee.redhat.com/rhidp/rhdh/-/tree/rhdh-1-rhel-9/.tekton -- you can probably merge those as is, then update them to match the customizations applied to the other fbc-related pipelines. 

image::images/new-application-fbc-component.png[New Application and Component]

### Removing support for EOL OCP versions

When support for an older version of OCP is to be dropped, FBC publishing for that old version can be stopped.

1. Delete the fbc application

2. Update lifecycle docs & official product docs, release notes, etc. 

3. Update defaults in link:https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/scripts/renderCatalogs.sh[build/scripts/renderCatalogs.sh] (and cherrypick to other branches if applicable)

## Installation

### via Helm

Helm charts for GA releases are manually created. See https://gitlab.cee.redhat.com/rhidp/rhdh/-/blob/rhdh-1-rhel-9/build/helm/prepare.sh

Each CI build produces a helm chart pointing back to that new build. As of 1.5, charts are here: https://quay.io/rhdh/chart

### via Operator

See link:RHDH-Konflux-user.adoc[RHDH-Konflux-user-guide.adoc].

See installation advice and scripts at https://github.com/redhat-developer/rhdh-operator/blob/main/.rhdh/

* install an IDMS/ICSP to resolve container image references
* install the latest FBC as a CatalogSource
