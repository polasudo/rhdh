# Performing a release in RH Internal Konflux 

Simply put, to release containers and FBCs, use this script:

* link:../build/scripts/kfuxRelease.sh[kfuxRelease.sh]

NOTE: The information below may be outdated as manual steps are replaced by scripted ones in the above script.

Sadly, we have two options for releases in Konflux:
* everything immediately released as long as the tests pass, or
* link:https://konflux.pages.redhat.com/docs/users/releasing/releasing-products.html#_authoring_releases[manual releases via yaml chunks] or using the clunky UI

1. find the set of snapshots you want to release. For 1.4 this is 3 containers and 5 FBCs.

2. Log into the cluster at https://console-openshift-console.apps.stone-prod-p02.hjvn.p1.openshiftapps.com/k8s/ns/rhtap-releng-tenant/core~v1~Pod using the link under your name to Copy login command. 

3. Run that command in a console, eg., 
+
```
oc login --token=sha256~YOUR_TOKEN_HERE --server=https://api.stone-prod-p02.hjvn.p1.openshiftapps.com:6443
```
+
4. Next, sequentially, appy Release yamls like this:

```
echo "apiVersion: appstudio.redhat.com/v1alpha1
kind: Release
metadata:
  name: manual-release-rhdh-1-4-fbc-4-14-stage-2
  namespace: rhdh-tenant
  labels:
    release.appstudio.openshift.io/author: 'nboldt'
spec:
  releasePlan: rhdh-1-4-fbc-4-14-stage-release-plan
  snapshot: fbc-4-14-d766t
" |  oc apply -f -
```

To watch the push in progress or review logs:

* Go to https://konflux.apps.stone-prod-p02.hjvn.p1.openshiftapps.com/application-pipeline/workspaces/rhdh/applications/fbc-4-16/releases
* Click on a release
* Click on the `managed-xxxx` link under `Pipeline Run` which will direct you to the `rhtap-releng-tenant` instead of your own `rhdh-tenant`.
* Click on `Logs` to review the success or failure.

Once successfully pushed to stage, you can pull containers to test installing them.

If you need a pull secret, you can use the one in the BitWarden vault called `rhdh_bot_registry_stage_redhat_io.user+pwd`

Note also this mapping: 

* If image is pushed to: quay.io/redhat-pending/rhdh----rhdh-operator-bundle:1.4
* refernce it as this:   registry.stage.redhat.io/rhdh/rhdh-operator-bundle:1.4

For IIBs/FBCs use these locations:
* brew.registry.redhat.io/rh-osbs/iib-pub-pending:v4.17
* registry.stage.redhat.io/redhat/redhat-operator-index:v4.17

And in production:
* brew.registry.redhat.io/rh-osbs/iib-pub:v4.17
* registry.redhat.io/redhat/redhat-operator-index:v4.17

To check that your stage push is the latest / correct version:

```
for d in /rhdh/rhdh-hub-rhel9:1.4 /rhdh/rhdh-rhel9-operator:1.4 /rhdh/rhdh-operator-bundle:1.4; do \
  for r in registry.stage.redhat.io quay.io; do
    echo; echo ${r}${d}; \
    skopeo inspect docker://${r}${d} > /tmp/inspect.txt && \
    jq -r '.Labels.version+"-"+.Labels.release+" built on "+.Labels."build-date"' /tmp/inspect.txt && \
    jq -r '.Env[]|select(.|contains("_REPO"))' /tmp/inspect.txt && \
    jq -r '.Labels."vcs-ref"' /tmp/inspect.txt && \
    rm -f /tmp/inspect.txt
  done
  echo "-----"
done
```
